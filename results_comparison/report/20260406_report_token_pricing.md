# Large Language Model Token & Pricing Report

This report provides a breakdown of API pricing based on the estimated token usage generated by the ZTF/ALeRCE multimodal astronomical alert classification benchmark.

## Part 1: Evaluation Parameters Driving Token Usage

The baseline token usage was derived from empirical measurements of the Kimi-K2.5 model via the Tinker platform on 100 few-shot examples and extrapolated to the full 2,500-example benchmark (500 per class: SN, AGN, VS, asteroid, bogus).

### Per-Example Token Breakdown

| Component | Tokens | Notes |
|-----------|--------|-------|
| System prompt (input) | ~2,050 | Fixed across all examples; image interpretation guide, metadata guide, Part A/B/C JSON schema, rubric |
| User prompt (input) | ~175 | Object ID + 18 metadata fields (band, magpsf, PS1 mags, sgscore1, etc.) |
| Image (input) | ~60 | Single PNG montage (225x111 px, ~22 KB); Science + Template + Image panels |
| Model output | ~611 | Structured JSON: Part A (6 fields), Part B (3 rationale strings + 3 self-scores), Part C (3 stages) |

### Aggregate Token Volumes

| Scale | Input tokens | Output tokens | Total tokens |
|-------|-------------|---------------|--------------|

| **2,500 examples (full benchmark)** | **5.71M** | **1.53M** | **7.24M** |

### High-End Estimate

The baseline of 7.24 million tokens was measured on Kimi-K2.5, which produces concise structured JSON. Closed-source models with more verbose reasoning (particularly Claude Opus, which tends to generate longer rationale strings in Part B) may produce longer outputs. Applying a **1.25x multiplier** to the baseline yields a high-end estimate of **9.05 million tokens**. This multiplier is conservative because the output format is constrained to a fixed JSON schema (Parts A-C), which bounds output length more tightly than free-form dialogue.

### Key Evaluation Parameters

- **Benchmark size:** 2,500 alert examples (500 per class, balanced across SN, AGN, VS, asteroid, bogus).
- **Multimodal input:** Each example includes a single PNG montage (Science | Template | Difference cutouts, 225x111 px) plus 18 tabular metadata fields serialized as text.
- **Structured output:** The model must return a single JSON object with Part A (metadata grounding, 6 fields), Part B (scientific rationale + 3 self-scores on a 0-5 rubric), and Part C (3-stage hierarchical classification).
- **Single-turn inference:** Each example is an independent, single-turn VLM call (no multi-turn dialogue or conversation history accumulation).
- **Output budget:** Max 2,048 output tokens per example; observed mean is ~611 tokens.

## Part 3: Key Observations

1. **Claude 3 Opus dominates cost.** At $200-$250 for the full benchmark, it accounts for ~60% of the total budget. Its $75/MTok output price is 5x more expensive than any other model tested. If budget is constrained, Claude 3 Opus should be run on the few-shot split first (100 examples, ~$8) before committing to the full benchmark.

2. **Budget-friendly options exist at every tier.** GPT-4o-mini ($1.77), Gemini 2.5 Flash ($5.54), and Claude 3 Haiku ($3.34) each cost under $7 for the full 2,500-example run, making them suitable for rapid iteration and ablation studies.

3. **Output tokens are the primary cost driver for premium models.** Despite representing only ~21% of total tokens, output tokens account for 60-83% of total cost for models with high output pricing ratios (Claude 3 Opus: 5x input-to-output ratio, gpt-5.4: 6x).

4. **The 1.25x multiplier is conservative.** Because the benchmark enforces a fixed JSON output schema (Parts A-C), output length is naturally bounded. Models that produce extended chain-of-thought reasoning before the JSON may exceed this estimate, but the structured format prevents the unbounded output growth seen in free-form dialogue benchmarks.
