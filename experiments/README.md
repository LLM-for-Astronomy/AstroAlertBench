# Experiments Log

Each `EXP-YYYYMMDD-<slug>.md` is a self-contained record of one VLM benchmark run, generated by the `log-experiment` skill (see `.cursor/skills/log-experiment/`).

## Naming
`EXP-{date}-{kebab-slug}.md` — e.g. `EXP-20260419-qwen35-think-newprompt.md`. If multiple runs share a date and slug, append `-2`, `-3`, …

## Conventions
- Reports are append-only after the **Results** section is filled. If you re-run, create a new EXP file and link to it from the **Baseline** section of the original.
- Always include the git commit hash; that is the single most important field for reproducibility.
- Set `Status: planned | running | complete | failed` so partial reports are obvious.
- `TBD` is acceptable for fields that depend on post-run evaluation. Update the file once data is available.

## Comparing runs
Two runs differ in three places: **prompt module**, **renderer/sampling config**, **code changes**. The **Code Diff vs Baseline** section captures the third; the rest is in the Configuration and Prompt Summary sections.
